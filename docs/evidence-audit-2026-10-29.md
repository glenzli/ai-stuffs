本轮基于本地提交 `d4f380b` 深化既有页面。保持 66 页与六步主线，增加两个公式，
当前共 143 个公式。新增两组独立证据，旧八组工件、问题、标签和训练权重保持原字节。
本轮补充完成时不提交或 push。

来源根目录为 `artifacts/evidence-audit-20261029034521Z/`，其中：

- `retrieval-comparison/`：固定真实排名上的候选融合、逐题配对和全部重采样分布；归档约 0.51 MiB。
- `text-evaluation-audit/`：从三份固定权重重新计算的逐位置损失、逐文档评价和加权重采样；归档约 11.23 MiB。

## 1. 候选覆盖与最终排序分别检查

入口：`retrieval-project.html#retrieval-hybrid`。沿用原 36 道问题、877 个段落及原始
BM25/Flat 实际前十名。每路取十条，按段落 ID 去重，再做截断 RRF，常数固定 60。
只为进入某路前十的段落加该路名次贡献，未进入的贡献为零，同分按段落 SHA-256 排序。
这与原“Flat 候选内重排使用全局 BM25 名次”的配方不同，分别保留来源和结果。

参数在本次追加运行前固定，没有搜索或选取最佳配置；但原问题集的结果此前已经查看，
所以这是一项探索性机制比较，不能重新称为未见测试集确认。新确认需要独立的问题与标注。

24 道测试题、12 个来源组的实测结果：

| 方案 | Hit@1 | Hit@5 | Hit@10 | MRR@10 |
| --- | ---: | ---: | ---: | ---: |
| BM25 | 70.83% | 91.67% | 91.67% | 0.782639 |
| BGE Flat | 50.00% | 66.67% | 70.83% | 0.578869 |
| 两路并集、截断 RRF | 66.67% | 79.17% | 91.67% | 0.728009 |

去重后每题平均 16.83 个候选。并集覆盖 22/24 题；BM25 额外提供 Flat 未找到的 5 题，
Flat 未额外提供 BM25 未找到的指定证据。本轮没有在最终截断时丢掉已覆盖证据。
混合方案恢复了更多候选，但其 MRR 低于更强的 BM25 单路，保留这项不利结果。
候选数量与两路请求不等于同计算或同延迟，未据此做生产性能结论。

新包包含原始完整检索报告的副本、36 道题的全部去重候选、两路名次与实际融合得分、
全部段落、八份可导入的配对 JSON 及每份按题/按组的完整重采样分布。它是保存排名上的
派生计算，没有重新编码；原编码器、向量和索引仍在原检索包中。

## 2. 真实配对数据连接浏览器统计工具

入口：`paired-evaluation.html?dataset=retrieval-comparison#pe-lab`。真实预设载入测试集
Flat → 混合的逐题 MRR@10，保留同一文档的两类提问及来源组，不改成模拟分数。
运行标签为 default，表示固定编码器，不代表额外训练了一个 seed。

Python 与浏览器独立实现使用相同公开协议：LCG uint32 seed=73、2,000 次、有放回
抽取相同数量的单位、原配对共同抽样、线性分位。按组时整组携带所有问题，以抽到的
题目数为分母。两端已逐项核对全部重采样值，而非仅核对区间端点。

| MRR 比较 | 同题平均差 | 按 12 来源组的 95% percentile 区间 | 赢 / 输 / 平 |
| --- | ---: | ---: | ---: |
| 混合 − Flat | +14.9140 pp | +8.6640 … +21.6270 pp | 10 / 0 / 14 |
| 混合 − BM25 | −5.4630 pp | −10.4884 … −1.0417 pp | 0 / 5 / 19 |

页面同时显示逐题抽样结果，说明独立单位假设如何改变分布；按组区间并不保证总比逐题
更宽，不能选择更窄的一种来强化结论。百分位区间对小样本的覆盖率没有保证；文档组还
需近似独立且有代表性。标注不穷尽、已查看数据、训练选择与部署漂移都没有被区间消除。
原评估工具里的交换检验仍附带其交换性假设，不把观察性方案差异当成随机化因果实验。

## 3. 从保存权重打开总体 CE

入口：`text-training-project.html#tp-document-audit`。加载原 seed 11/29/47 的第 800 步
最终 checkpoint；全部训练、验证和测试窗口重算每个有效标签的 NLL 和 top-1 预测。
保存全部逐位置数组；未训练、未选择新 checkpoint、未合并不同 seed。

每篇文档保留标签数、NLL 总和、正确数、窗口数、bigram 参考和 CE 改善。
token 微平均使用所有 NLL 除以所有标签数，文档宏平均让每篇文档的 CE 等权。
两种口径分别报告，不把改变权重解释成模型进步。

| 测试 seed | token 微平均 CE | 文档宏平均 CE | 优于 bigram 的测试文档 |
| --- | ---: | ---: | ---: |
| 11 | 3.171643 | 3.166786 | 8 / 8 |
| 29 | 3.170038 | 3.164227 | 8 / 8 |
| 47 | 3.149952 | 3.147290 | 8 / 8 |

完整测试集仍为 22,731 个标签、8 个文档。与原报告的整体 CE 最大绝对差约 1.1e−7，
来自逐位置 double 累计与原分批 float32 归约；核验阈值 2e−6，旧数值和旧快照未改。
独立测试改用 13 条一批，并通过 log-softmax/gather 重算每个 NLL 和全部预测。
bigram 的文档损失另从 NumPy 计数概率矩阵计算。

文档重采样同时抽取旧/新 NLL 总和及标签数，重算总差值除以抽中标签总数；
没有把“每文档 CE 差等权平均”冒充 token 微平均差，也没有把 22,731 个相关标签视为
同量独立样本。区间以一个保存模型为条件，不包括训练 seed、近重复和领域迁移的波动。

## 重跑与核验

沿用 `scripts/framework-requirements.txt` 的 PyTorch 2.9.0 / NumPy 2.3.4 独立环境：

```bash
npm run lab:audit -- --out-dir artifacts/audit-my-run
npm run test:evidence-audit
```

runner 只读已登记来源，验证原输入和权重身份，保存实际运行环境、源码副本及哈希。
默认两项依次运行；可加 `--only retrieval-comparison` 或 `--only text-evaluation-audit`。
已有输出目录会被拒绝，不覆盖默认来源。核对候选后显式采纳：

```bash
npm run accept:experiment -- --candidate \
  artifacts/audit-my-run/retrieval-comparison/candidate.json \
  artifacts/audit-my-run/text-evaluation-audit/candidate.json
```

每包解压后，在实验 ID 子目录核对 `SHA256SUMS`，在解压根目录核对
`SOURCE-SHA256SUMS`。检索包可从自己的 `retrieval-source.json` 离线重算；文本包包含
`inputs/` 下三份原始 checkpoint、窗口、tokenizer、原始模型报告和 bigram 报告，源码副本
包括模型实现与固定依赖清单。

新增 Python 核验覆盖独立重采样分母、手算融合、全部真实候选、所有切片指标、三 seed
全部逐位置重算、NumPy bigram 参考和各文档分布。Node 对照浏览器实际统计模块，核对
每份 Python 重采样分布、真实预设、来源投影、分母与页面链接。真实浏览器另检查控件、
参数恢复、预测题、候选展开、源码下载、手机和平板布局及暗色主题。

本轮验收记录与截图见来源根目录下 `verification-summary.json` 与 `qa/`。
