## 比较对象和监督规则

复用原文本项目 seed 11 第 800 步的最终权重、387 类 byte BPE、两个 width=96 的完整
Transformer block，共 298,176 个参数。从原训练窗口中按保存顺序取前四个完整 96-token
窗口，不重新采样。输入全部保留，按条件只让每条记录末尾的指定数量目标参与监督；其他
shifted targets 变为 −100，不再移位。这是隔离监督计数的人工 mask，不是聊天模板或新 SFT
能力实验。

所有分支使用同一份权重，统一转为 CPU float64。模型无 dropout；不使用 AMP 或梯度裁剪。
每次比较只更新一次。两种优化器分别与自己的完整 batch 参考比较：

- AdamW：恢复同一份第 800 步优化器状态，LR=0.002、weight decay=0.01。
- SGD：同一权重、全新无动量状态，LR=0.01、weight decay=0.01。

梯度读数是 token CE 的导数；优化器的衰减、历史矩和步数另进入参数/状态比较。
因此梯度缩放比例不能直接当成参数位移比例，也不以本实验比较优化器的学习质量。

## 五个冻结条件

| 条件 | 每条监督标签 | 单进程累积或 DDP 切分 | 核验目的 |
| --- | --- | --- | --- |
| 不等量监督 | 4 / 8 / 40 / 96 | 单进程微批为 12 / 40 / 96；DDP 副本为 44 / 104 | 微批均值和副本均值的权重会变 |
| 等量对照 | 16 / 16 / 16 / 16 | 四个微批各 16 | 记录“均值等权”在本条件下也成立 |
| 尾窗口 | 16 / 16 / 16 | 实际 3 个微批、计划 4 个 | 不能把实际尾窗口仍除以计划步数 |
| 全局空监督 | 0 / 0 / 0 / 0 | 无有效 token 目标 | 跳过与“零损失仍 step”的参数/状态不同 |
| 一个空副本 | 0 / 8 / 0 / 96 | rank 0 为 0，rank 1 为 104 | 空副本仍参与通信，不能用副本均值平均代替全局目标 |

完整 batch 使用有效标签的总和作为分母。正确累积路径将每个微批 loss sum 除以整个
更新窗口的 N。实际 DDP 启动两个 CPU Gloo 进程，先归约全部标签计数，局部 loss sum
乘 P/N，再由默认 DDP 对参数梯度除以 P。每个副本有两个微批，第一次的前向和反向均在
`no_sync` 中，最后一次同步；没有使用自定义通信 hook。

错误的本地均值方案在空副本上显式补零，作为单独的负例保留；它没有把空均值宣称为定义良好。
全局 N=0 时，正确参考与累积路径均不反传、不调用 optimizer，均值显示“无定义”。
保存的零梯度向量只用于比较占位，不是声称执行过反向传播。

## 保存的实际结果

正确累积和 DDP 路径的全部参数梯度、更新参数与优化器状态均在 2e−10 容差内吻合完整
batch。CPU double 的规约顺序仍有约 1e−16 到 1e−14 差异，未宣称跨系统逐 bit 相同。
AdamW 的代表性负例如下，完整来源也保留 SGD 和等量对照：

| 条件与错误方式 | 梯度最大绝对差 | 更新后参数最大差 | 额外观察 |
| --- | ---: | ---: | --- |
| 不等量微批均值等权 | 0.108165 | 0.004809 | 改变了 token 权重 |
| 尾窗口仍除以 4 | 0.045536 | 0.000716 | 梯度 L2 比为 0.75 |
| 不等量 DDP 本地均值平均 | 0.051285 | 0.001744 | 改变了副本权重 |
| 空副本补零后平均 | 0.101120 | 0.001573 | 梯度 L2 比为 0.5 |
| 全局空监督仍更新 | 0 | 0.003218 | Adam 步数从 800 到 801 |

等量微批均值等权仍在容差内成立。全局空监督的正确路径保持参数、优化器状态和历史
步数不变；错误零损失路径虽有零梯度，历史矩或衰减仍推进参数。实验没有 scheduler、
GradScaler 或异步数据 worker，其状态策略需在实际训练流水线中另行明确。

## 工件、独立副本与去重

完整来源包含原始 checkpoint/优化器状态、tokenizer、窗口与源报告、明确的 mask 规则、
每条实际完整梯度向量、两个 rank 的环境和进程 ID，以及一次更新后的参数与优化器状态。
两 rank 各自生成实际输出哈希，并通过 Gloo 交换核对；梯度向量两边分别保留。
参数与状态哈希一致后只保存一份输出，双方报告保留各自哈希见证，不能用单独一份文件
冒充两边独立运行。

最初完整归档为 107.59 MiB，超过 GitHub 单文件上限，未采纳。随后在独立比较并确认
输出一致的前提下，去除重复参数/状态文件并捕获新源码重跑，完整归档为约 73.63 MiB。
数学工作负载保持不变，记录见 `qa/packaging-history.json`；最初目录作为本地历史保留。
没有删除不利结果或降低精度来压缩证据。

## 运行和采纳

```bash
npm run lab:accumulation -- --out-dir artifacts/accumulation-my-run
npm run test:accumulation
npm run accept:experiment -- --candidate artifacts/accumulation-my-run/candidate.json
```

沿用 `.venv-framework` 的 PyTorch 2.9.0 / NumPy 2.3.4，需要允许本机 loopback 通信；
不下载新模型或外部语料。runner 只准备候选，拒绝已有输出目录。采纳同时核对完整归档、
原始校验表、运行时源码和页面投影；这些命令不执行 Git 提交或 push。

本轮还从实际下载包解压的源码和输入独立运行一次数值实验：工作目录放在临时目录，
清空 PYTHONPATH，不从当前仓库导入源码。34 条结果的 102 个误差字段在容差内吻合，
34 条参数哈希和 34 条梯度文件哈希均一致，两个新 worker 的进程 ID 不同。
证明记录与重放报告分别保存在 `qa/bundled-replay.json`、`qa/bundled-replay-report.json`。

下载包解压后，也可以按以下结构自行重放，使用已安装固定依赖的 Python：

```bash

cp -R accumulation/inputs replay-input/text
python source/scripts/accumulation_lab.py \
  --out-dir replay-result --practice-directory replay-input
```

`replay-result` 必须尚不存在。解压根目录的 `SOURCE-SHA256SUMS` 与实验子目录中的
`SHA256SUMS` 分别核对源码及全部原始工件。
