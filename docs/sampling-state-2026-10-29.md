## 补充的内容

入口：`decoding-algorithms.html#sampling-state`。
推理页和复现实战页也提供入口；默认折叠账本，直接加载该锚点时展开。

新内容区分三个容易混淆的对象：某一步的采样分布、分给该请求的随机位置，
以及由两者选中的 token。改变取数位置后仍可能抽中相同 token；
只比较最终文本会漏掉已经发生的随机状态变化。

这是一项固定分布计算演示。概率与 u 清单人为指定并完整公开，
没有加载模型或产生新的训练测量，也没有新增第十四组模型实测。
浏览器复用原解码页的 `sampleFrom` 逆 CDF 实现，不另写一套采样规则。
三请求分布在所有轮次保持固定，B 是否一步后结束由手工预算控制，不由输出 token 决定，
因此本例不处理 EOS 或自回归前缀引起的分布反馈。

## 三种归属和两个参考

| 归属 | 怎样取数 | 调度变化时需看什么 |
| --- | --- | --- |
| 全局流 | 按执行顺序消费同一清单 | 请求重排、提前离开会改变分配 |
| 批次槽位 | 槽位 0/1/2 各有清单与游标 | 压缩后的槽位可能属于另一请求 |
| 请求 ID | A/B/C 各保留自己的清单与游标 | 本例中每个请求的共同步保持一致 |

第一张账本将当前调度与“ABC、按请求 ID、每请求三步”比较，
按请求及步数对齐；提前结束后没有输出的步骤不记作差异。
清单特意使 ABC 且不提前结束时三种策略完全对齐，方便隔离调度变化。
这种安排不证明各流在统计上独立，也不检验随机数生成器质量。

第二张账本将暂停后运行与“当前同一调度的连续运行”比较，避免把调度差异当成恢复差异。
保存内容包括下一事件位置、已生成前缀和所有流的游标，并经 JSON 序列化后接续。
恢复选项分别保留保存游标，或把游标重置为初态。
暂停发生在开始前和全部完成后时，重置不能凭空产生后续取数差异；这些边界单独覆盖。

## 可手算的例子

默认 CBA、全局流、三步的第一轮中，C 拿到 `u=0.12`。
C 的累计概率为 0.10、0.30、1.00，所以输出 y；参考 C 的 `u=0.34` 输出 z。
A 拿到 `u=0.34` 输出 y，参考 A 的 `u=0.12` 输出 x。
完整九步有六次取数不同、四次 token 不同。

ABC、按槽位且 B 一步后结束时，C 在下一轮从槽位 2 移到槽位 1，
拿到 0.49，之后拿到 0.72；按请求 ID 的参考是 0.91 和 0.05。
A 一直保留槽位 0，在此例不受这一压缩影响。

默认调度消费四个数后重置全局游标，下一步 B 的取数从参考 0.49 变为 0.12。
B 对 x 的概率为 0.50，这两个位置都输出 x。
页面分别报告首个取数差异与 token 差异，保留这一有用反例。

## 与真实生成器的关系和边界

PyTorch 2.9 的 [Generator 文档](https://docs.pytorch.org/docs/2.9/generated/torch.Generator.html)
分别提供初始 seed 与 `get_state` / `set_state`，用于保存、设置生成器当前状态。
其 [复现说明](https://docs.pytorch.org/docs/2.9/notes/randomness.html)还限定了版本、平台和设备间的复现保证。
两份固定版本的一手文档于本轮重新读取。

此处的游标是有限清单的状态表示，没有模拟某个框架 seed 的输出，
没有比较 CPU/GPU 采样器，也不声称只按请求分流即可解决所有复现问题。
如果实际系统要求请求在批次重排后保持样本路径，仍需核对分布、采样算法、流映射与状态，
以及批次形状带来的浮点变化。真实接续还需保留前缀、采样配置、对应 KV 和执行进度。

全局流导致样本路径随调度变化，本身不构成“分布有偏”或“实现错误”的证明；
是否违反要求，取决于系统有没有承诺请求级路径稳定。本例展示这个条件关系。
