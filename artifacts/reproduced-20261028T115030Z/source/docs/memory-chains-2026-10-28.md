## 机制与数值边界

Attention 反传使用五位置、二维 Q/K/V/G，无 dropout，目标为 `Σ O⊙G`。
前向在线累计，保存 O 和行 LSE；反向每次重建一个概率块。完整参考用整行 softmax，
逐元素有限差分独立核对 Q/K/V；Python 再以完整矩阵 autograd 核对。
空 query 行明确定义输出及导数为零，避免计算无定义 softmax 或 `−∞−(−∞)`。
错误局部 softmax 只作用于反向；错误覆盖 K/V 展示多个 query 块的梯度贡献丢失。
只有一个 key/query 块时，相应故障可能不暴露，测试覆盖这些反例。

Attention 逻辑账本分别列 Q/K/V/O、完整 P 或 LSE、临时概率块、G/dQ/dK/dV。
默认 5×5 概率矩阵 25 元素，LSE 5 元素，概率块最多 4 元素；因果有效 QK 点积
前向 15 次、反向重建 15 次。其他临时量、物理副本、矩阵乘 workspace 和教学事件快照
不在概率块容量内，不把这个计数称为物理内存峰值。

梯度缓存使用 4 对样本、3→4→2 无 bias 编码器、tanh 与 dropout，4×4 全局点积候选。
页面用 LCG seed=31，按固定样本/块顺序生成 inverted-dropout mask。第二阶段得到每个
表示的梯度，第三阶段固定该梯度作为 VJP 上游，全部块完成后才可更新参数。
正确重算恢复各块的前向 RNG，结束后保留第一遍编码完成时的 RNG，不额外推进下一步。
参考采用相同分块和随机轨迹而保留计算图；不要求任意 batch 形状下的框架随机数逐位一致。

默认梯度缓存 loss≈1.3432816511475403；恢复 RNG 的重算和参数梯度差均为零。
不恢复 RNG 时缓存 loss 不变，重算表示最大差约 0.294791、参数梯度最大差约 0.056406。
关闭 dropout 后这个故障不产生差异。逻辑隐藏量计 H、mask、Z 三份四维张量：完整保留
96 元素、chunk=2 时最多 24 元素；表示 16、表示梯度 16、候选矩阵 16 元素另计。
页面保留对照快照仅服务教学，不声称浏览器实现实际节省这些内存。

裁剪固定同步后的梯度、scale=8、参数初值 1、无动量 SGD η=0.1。
每个独立参数指定一个 rank 计数，副本使用相同全局系数；精确比例不添加 epsilon。
分片 `[3] / [4]` 的全局范数为 5，阈值 1 的结果 `[0.6,0.8]`；逐卡裁剪为 `[1,1]`。
混合布局额外复制梯度 12，独立范数 13；重复统计会得到 `sqrt(313)`。
全部复制布局下本地范数可能正确，无复制布局下物理计数可能正确，测试分别覆盖。
任何 rank 非有限时正确协议统一跳步；故障模式只在本地决定是否更新，显示版本分叉。

Gloo 采用自定义唯一拥有者归约协议，不调用 FSDP API，也不实现完整 GradScaler。
为让所有故障配置执行相同顺序，验证程序固定归约非有限标志、唯一平方和及物理平方和；
生产协议可以在全局确认无效后一起跳过范数归约，不能单 rank 自行改变 collective 顺序。

## 独立实验与实测结果

```bash
npm run lab:memory
```

可使用 `-- --out-dir <新目录>`，已存在目录拒绝覆盖；环境安装见 README。
最终记录在 `artifacts/memory-lab-2026-10-28-final/`，2026-10-28 09:55（Asia/Shanghai）生成。
环境为 Python 3.12.14、PyTorch 2.9.0、macOS 15.7.3 arm64、CPU float64、一个计算线程。

- 144 种 Attention 配置（块 1/2/3/5，三种 mask，三种反向路径）。
- 24 种梯度缓存配置（chunk 1/2/3/4，dropout 0/0.25/0.5，正确与错误 RNG）。
- 60 种裁剪配置（五种布局、四种协议、三个阈值），实际运行两个 Gloo 进程。
- 真实 PyTorch dropout 额外检查 4 种 chunk × 恢复/不恢复 RNG；恢复时最大梯度差
  约 1.39e-17，不恢复时约 0.056252。正确模式还核对后续 RNG 状态。
- 共 1,291 项数值比较通过，最大绝对差 1.5543122344752192e-15，atol=1e-9、rtol=1e-8。

独立测量在验证通过后运行，预热 3 次，再测 12 次。保存张量统计和 profiler 各另跑一次，
不计入耗时；梯度缓存的逐块误差诊断也从计时路径排除。调用耗时包含对应 Python

Attention 测量使用 N=64、d=16、query/key 块 16。缓存使用 32 对样本、16→64→8、
chunk=8、dropout=0.25，两个方案使用同一分块随机轨迹。裁剪仅测 4096 元素的本地算术，
不含真实通信时延；双进程通信正确性另行验证。

保存量由 `saved_tensors_hooks` 跟踪同时存活的保存对象所引用的唯一 storage，
包含被引用的输入和参数；view/别名按 storage 去重。不统计未保存的临时量、分配器
reserved memory、进程 RSS 或 GPU 峰值。0 表示该操作没有自动微分保存对象，
不表示没有内存分配。固定 CPU 的 Python 分块实现更慢，这些读数不外推 GPU kernel。
