## 1. 小模型的训练、生成与泛化

本地依据：`src/scripts/features/checkpoint-replay.js` 使用四条固定二维输入和末位置标签，
主要比较连续训练与恢复轨迹。`scripts/framework-reference.py` 核对同一小模型的梯度、
八步更新和恢复。`src/scripts/features/rl-update.js` 已有真实参数更新，但回答和状态特征固定。
当前这些实验并未组成一套可训练序列任务的独立泛化评估。

建议新增一个 CPU 可运行的小型 decoder，配固定符号词表、位置编码和无需下载的任务生成器。
先选一种规则明确的任务，例如短序列变换或键值关联检索；固定模型规模、预算和数据拆分，
训练前后都保存逐题预测。minGPT 的作者仓库提供排序、加法和字符建模的教学组织参考，
但仓库已注明 semi-archived，本建议不把它作为新依赖或维护状态推荐。[S1]

需要分别呈现：

- 训练集上的拟合与同分布未见组合上的正确率。
- teacher-forced token loss、自由生成的逐 token 正确率和整段 exact match。
- 长度外推、未见模板或组合变化；每种变化单独定义，避免混成一个总分。
- 简单基线、多个训练 seed、实际参数量、消费 token、更新次数和保存的预测。

数据拆分按实际问题或生成因素进行，并验证题目与答案没有意外重叠。
长度外推集保留为独立评估，不用反复调参。简单任务可能被复制或频率规则解决，基线必须能暴露这一点。

验收应包括模型能在固定训练集上拟合、生成与增量缓存前向一致、保存/恢复后评估一致，
以及页面能读取本次真实运行的曲线和预测。未见组合或长度上的结果允许失败，应如实解释，
不把某个小模型成功外推描述成语言模型的普遍能力。

建议归属：一个完整学习实验入口，连接训练回路、位置缓存、工件、模型评估与配对统计。

## 2. 真实故障、首个异常与回放

本地依据：`src/content/optimization-dynamics.html` 已要求回放异常 batch；
`src/scripts/features/engineering-cases.js` 的诊断记录为预设案例，
`src/scripts/features/checkpoint-replay.js` 负责恢复状态遗漏的对照。
新增内容可以让读者实际看到日志证据如何产生。

建议沿第一项的小模型训练记录每层激活 RMS、最大绝对值、有限性、梯度范数和参数位移。
在更新前保存 checkpoint、样本 ID、RNG、数据位置、mask、学习率和运行配置。
故障例子分别选择数值异常、优化异常和监督异常，例如：

- 特定输入导致某次不稳定指数计算产生首个非有限张量。
- 过大的学习率在更新后放大参数，异常在下一次前向才出现。
- 标签错位使所有张量保持有限，但预测目标与任务契约不一致。

每次只注入一项，回放同一个 checkpoint 和相同输入，显示首个不同张量和后续传播。
修复后重跑原失败样本与正常对照；检查修改是否只压低了幅度，还是恢复了正确目标与轨迹。
有限性检查不能证明语义正确，梯度裁剪也不能替代目标核验。

本机 PyTorch 2.9.0 的 `torch.autograd.detect_anomaly` 文档已核对：它可提供失败反向操作
对应的前向 traceback，并在指定检查下报告反向 NaN，但有额外运行开销。
因此只用于定向诊断，不能被描述为所有数值或数据问题的自动根因分析器。[S2]

验收应包含固定种子复现、日志中可定位首个异常、修复后通过同一参考比较，
以及一次“无 NaN 但训练目标错误”的反例。

建议归属：深化工程诊断案例与优化稳定性页，共用学习实验报告，不再单独编造结果曲线。

## 3. 初始化、残差和 μP 的尺度实验

本地依据：`src/content/optimization-dynamics.html` 的初始化部分为概念说明；
`src/scripts/features/backpropagation.js` 只有一个固定宽度 block；
`src/content/scaling-laws.html` 已提到 μP 与坐标检查，但没有多宽度计算。

建议分成两组受控实验：

1. 固定宽度，改变深度、残差缩放和 Norm 位置，记录初始化与少量更新后的逐层激活和梯度尺度。
2. 固定深度、任务和优化器，改变宽度，比较明确声明的标准参数化与 μP 参数化。

先用足够简单的网络把 fan-in、readout 和参数组缩放讲清，再连接小 decoder。
μP 的作者实现明确区分输入、隐藏层和 readout，并用不同宽度下的激活坐标量级检查实现。
坐标检查只是诊断证据，不保证某个任务上最佳学习率一定相同；还应进行小范围学习率扫描，
保留一个未参与选择的宽度作验证。[S3]

Pre-LN/Post-LN 的比较需要声明 Norm 形式和论文假设。Xiong 等的论文讨论初始化时的
梯度与 warmup 关系，结果不应被推广成“Pre-LN 在任意网络、优化器和预算下都不需要 warmup”。[S4]

验收应使用多个 seed，分开初始尺度与更新尺度；报告参数组的初始化方差、实际 LR 和 readout 因子。
宽度迁移与深度变化单独实验，禁止同时改两者再把收益归因于 μP。

建议归属：深化优化稳定性与 Scaling Laws，复用第一项的训练与评估工件。

## 4. Batch、梯度噪声与训练预算

本地依据：`src/content/optimization-dynamics.html` 已说明 batch、噪声和更新次数关系，
`src/content/parallel-correctness.html` 已覆盖累积分母；当前没有真实逐样本梯度分布及 batch 扫描。

建议先固定模型参数，在同一数据集合上计算每个样本的梯度。
定义样本为独立序列，先固定各序列内部的监督归一化，避免把相关 token 当成独立样本。
计算平均梯度、协方差迹和不同 batch 的方向/范数分布。

在固定参数、独立同分布且有放回抽样的前提下，batch 平均梯度的协方差为单样本协方差除以 B。
有限数据集无放回抽样则需要有限总体修正；两者分别标注。
可用小数据集穷举采样组合核对该关系，再用重复采样观察频率。

随后才运行实际训练：保持总消费 token 与评估集固定，对照 batch、更新次数和学习率，
明确 scheduler 使用 step 还是 token。每条曲线记录真实运行值，不能由预设噪声公式直接生成。
梯度噪声尺度研究提供 batch 选择的经验动机；本轮只核对论文摘要，
具体估计器与实施假设须在实现前继续读取正文。[S5]

验收应包含平均梯度接近零时的指标边界、重复样本与相关样本的反例、固定预算比较，
以及真实训练结果对简单噪声估计的偏离。这个统计量不直接给出任意 AdamW/裁剪配置的最优 batch。

建议归属：优化稳定性页的深入实验，连接微调预算、性能分析和配对评估。

## 5. 分块输出投影与交叉熵

本地依据：`src/scripts/features/vocab-parallel.js` 对六个预设 logits 计算分片 CE 和 p−y；
`src/scripts/features/backpropagation.js` 的输出头先形成完整 logits，再传回 hidden 和权重梯度。
现有分块 Attention、梯度缓存和量化矩阵乘可以作为该专题的先修内容。

建议固定 hidden 矩阵 H 与词表输出权重 W，分块计算 H×Wᵀ。
前向累计每行 log-sum-exp 与目标 logit，反向重建每块概率，累计 dH、dW 和可选 bias 梯度。
以完整线性层加 CE 的 PyTorch autograd 作为独立参考。

一个具体账本：8,192 个预测位置、131,072 词表项，单份 FP16 logits 就有
8,192×131,072×2=2,147,483,648 B，即 2 GiB。这只计该张量，不含 dtype 转换、梯度、
输入、权重或其他模型状态；不能直接当作端到端峰值。

Apple 的 Cut Cross-Entropy 作者实现提供不物化完整 logits 的动机与接口，
同时区分梯度过滤和不进行该过滤的参考模式。教学第一版应保留全部梯度贡献，
验证声明的精确目标；若随后展示阈值过滤，须明确它带来的近似。[S6]

验收应覆盖不同 token/词表块大小、尾块、忽略标签、零有效位置、稳定大幅平移、
目标处在不同词表块，以及 hidden 梯度多块累加。若接入权重绑定，还要检查输入查表和输出投影
对同一参数的梯度求和。保存量、重算工作和独立 CPU 时间分别记录，不宣称教学循环达到 GPU kernel 性能。

建议归属：独立输出层计算专题，连接词表并行、反传、性能与权重绑定。
