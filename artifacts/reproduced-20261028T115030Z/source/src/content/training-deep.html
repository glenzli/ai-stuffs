02

Mask、padding 与有效梯度

这些设置会改变有效监督位置，以及梯度进入参数的路径。

屏蔽 padding 会影响哪些计算路径？

attention mask 排除 PAD 键，loss mask 排除 PAD 标签位置，padding_idx 可阻止 lookup 算子累加该行梯度；三者作用不同。ignore_index 不删除有效位置 softmax 中的 PAD 类别，因此绑定输出表仍可能使 PAD 行收到梯度。PAD 与 EOS 共用 ID 时，尤其不能按 ID 把有效 EOS 标签一并屏蔽。

为什么 log-softmax 比先 softmax 再 log 稳定？

直接除指数和容易溢出。稳定实现先减去最大 logit，再用 logsumexp。InfoNCE 也应在 logits 空间做 cross-entropy；把极小或极大的概率手动乘除会破坏数值稳定性。

稀疏 gather 会让 embedding 训练省显存吗？

前向只取少数行，但优化器状态是否省取决于实现。若使用 Adam，整个 E 的矩状态仍可能驻留；分布式训练还要做 all-reduce。有些系统用稀疏梯度或分片 embedding，但会换来通信和采样复杂度。

一个 batch 只有几条样本，为什么 loss 仍能覆盖整个词表？

完整词表 softmax 的分母含 V 个类别，非目标类的 logit 梯度为 p，目标类为 p−1。输入 lookup 只散射到被访问的行；输出投影通常是稠密梯度，绑定时也会加回 E。sampled softmax 和 SGNS 属于另外的计算或目标设置。

为什么 batch 内负样本会随 batch 大小变化？

每个其它样本的正文档可能成为当前 query 的负例。batch 越大，噪声候选越多、负样本越丰富，但显存和通信成本也更高；而 in-batch 样本越多，也越可能混入 false negatives。

05

InfoNCE 的梯度，逐项长什么样？

对一个 query 行，正样本的概率 pi 与负样本概率 pj 共同决定反传梯度。

01 / SCORE
z_{ij}=\frac{q_i^\top d_j}{\tau}

先归一化再点积时，这就是 cosine / τ；内积训练则不一定归一化。

02 / LOSS
\mathcal L_i=-\log\frac{e^{z_{ii}}}{\sum_j e^{z_{ij}}}

对角候选是正例，其他列是负例或 in-batch negatives。

03 / LOGITS
\frac{\partial\mathcal L_i}{\partial z_{ij}}=p_{ij}-y_{ij}

这是 softmax + 交叉熵最常用的梯度；y 在正候选位置为 1。

04 / QUERY
\nabla_{q_i}\mathcal L_i=\frac1\tau\sum_j(p_{ij}-y_{ij})d_j

这是对 q 的导数；梯度下降方向与它相反。更新含朝正文档、远离负文档的分量，最终是各项的向量和。若 q 是归一化后的输出，还要继续穿过归一化算子。

难负例与假负例要按任务标注区分。“主题相关但不能回答”可以是合理难负例；真正满足相关性标准、却因漏标被当成负例的才是假负例。两者的分数导数都为 pij/τ ≥ 0，更新会压低分数，后者因此损伤有效证据。可用多正例目标、重复文档屏蔽与标注复核处理。

归一化也在计算图里。若 q 是单位向量，u 是归一化前的非零输出，继续反传时还要穿过归一化的 Jacobian。
