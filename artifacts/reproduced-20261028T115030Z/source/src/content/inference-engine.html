ARCHITECTURE / INFERENCE ENGINE

自回归推理的两个阶段：prefill 与 decode

prompt 可以并行计算并填满 KV Cache；生成阶段每轮只新增一个 token，却要重读所有历史 K/V。 这两阶段的瓶颈、延迟指标和 batch 策略完全不同。

KV Cache 是什么

KV Cache 保存推理中已处理位置的 K/V，按层、head 和序列位置组织。后续 token 可复用这些状态，减少重复计算。

01

prefill 与 decode 怎样计算

同一组权重，处理 token 的方式不同：prefill 并行吃整段 prompt，decode 逐个追加。

PREFILL

一次并行处理整段 prompt

所有 prompt token 同时经过各层，计算 self-attention；输出最后位置的 logits，同时缓存每一层的 K/V。通常更偏 compute-bound，决定 TTFT 的主体。

tokens_compute = prompt_length
→
DECODE

输入上轮 token，预测下一个

首 token 由 prefill 的最后位置 logits 采样。decode 将它作为下一次输入，逐层计算新 Q/K/V、读取历史 KV 并追加本位置的 K/V，再预测后一个 token。小 batch 常受权重与 KV 读取带宽限制。

new_tokens = 1 per decode step
TTFT排队 + prefill + 首个 token
TPOT / ITL每个后续 token 的 decode 间隔
总生成时延TTFT + (N−1) × TPOT

04

Attention 的计算量与数据访问量

大 O 记号帮助看增长趋势，但真实延迟还受内存层次、kernel、batch 与序列调度影响。

PREFILL

更多是并行矩阵乘

投影与 MLP 是大的矩阵乘，GPU 利用率高；self-attention 的 token 交互项随 S² 增长。长 prompt 是吞吐与 TTFT 的主要压力。

attention interaction ≈ O(S² d)
DECODE

每步算得少，却要搬很多 KV

单 token 的 Q 很小，历史 K/V 读取量随 S 增长。GPU 可能更多在等内存带宽，而不是算术单元；批处理可提高总吞吐但增加缓存。

KV read ≈ O(S · L · Hkv · dhead)
WEIGHTS

每步都要过全部层

decode 每生成一个 token 都要遍历 L 层投影、MLP/MoE 与最终 head。权重读取通常占固定大块成本，MoE 可减少每 token 的专家计算但增加路由。

layers = L every token
05

真实 serving 系统在做什么

这些方法主要改进请求调度、缓存管理和执行效率。

CONTINUOUS BATCHING

每轮动态补请求

一个请求结束后立刻释放槽位，不等整批结束。prefill 与 decode 请求可以交错调度，提高 GPU 利用率。

PAGED ATTENTION

KV 分页，避免预留巨大连续空间

把每条序列的 KV 切成块，按需分配与回收。减少内存碎片和过度预留，也方便连续批处理与共享 prefix。

PREFIX CACHE

相同系统提示或文档前缀复用 KV

还必须匹配实际前缀 token/模态输入及其顺序、模型与 adapter 权重、位置和 attention 配置等缓存键；只比较用户文本不够。命中缓存能省前缀计算，但存储、淘汰与权限隔离仍需设计。

CHUNKED PREFILL

把长 prompt 切片调度

避免一个超长 prefill 独占 GPU 很久，让正在 decode 的请求也能获得执行机会，但会增加调度与时间指标复杂度。

SPECULATIVE DECODE

小模型猜，大模型验

用 draft 模型提出多个 token，再由目标模型并行验证接受。收益取决于接受率、验证成本和草稿模型的额外计算。

KV QUANTIZATION

更少 bytes，更多误差

FP8/INT8 缓存可减少带宽与显存，但可能影响长上下文质量；还要注意 scale、分组与 kernel 支持。

缓存前后 logits 是否一致下一 token 怎样被选出来分块 Attention 的归一化账本

    07 / CACHE OWNERSHIP

    共享前缀为什么需要引用、版本和回收规则？

    匹配的是完整计算条件

    同样文本未必同样 token。模型版本、adapter、位置、模态输入和缓存隔离信息都可能影响键；块内容还依赖此前前缀。命中前必须确认上下文计算条件兼容。

    释放引用与驱逐是两步

    请求结束可以减少引用计数。引用为零的块可被保留为缓存，也可被回收覆盖；仍被其他请求使用的块不能直接覆盖。

    共享块应保持不可变

    完整前缀块可供多个请求只读使用。分支继续生成需要私有尾块；如果系统允许共享未满尾块，写入前通常需要复制或其他隔离机制。

    缓存省去什么

    命中的前缀 K/V 可复用，后续 query 仍要读取相关历史状态。Prefix cache 节省的主要是相同前缀的重复 prefill；实际时延还取决于查找、搬运和剩余计算。

    生成输出与缓存边界逻辑位置与物理存储综合检查：输出比缓存多一位
