数据清洗与 Tokenizer：定义模型看见的世界

tokenizer 的词表和切分规则影响序列长度、embedding 表大小，以及中文、代码和数字的切分粒度； 数据清洗与去重决定模型反复看到什么；验证集污染会让训练曲线看起来很好却不可信。

检查数据的起点

先问“这些 token 从哪来、重复多少次、和评估集有没有重叠、tokenizer 版本是否固定”。这些信息有助于定位数据分布和评估方面的问题。

从原始语料到训练 shard

每个处理环节都应记录输入输出、统计、版本和拒绝原因，便于复查清洗结果。

01规范化

统一可比较的文本形式

Unicode 规范化、编码修复、HTML 清理、语言识别与元数据补全。保留原始文本，并记录清洗规则及输出摘要，以便复查不可逆改写。

输入 / 输出

原始文档 → 规范化文档 + 语言/来源元数据

关键指标

语言分布、截断率、编码错误率、每来源文档/token 数量

典型失败

全角/半角或代码缩进被误改；语言识别把混合文本误判。

序列长度与参数量的折中

03

数据混合：按 token 分配预算

拖动来源比例。有效训练预算按 token 而不是 GB；同一段中文、代码和英文的 token 密度不同。

混合后训练预算 100B tokens

实际训练还要决定采样温度、课程顺序、各来源的 repetition cap 与质量分层。来源占比描述训练投入，对应能力的变化还要通过任务评估确认。

04

训练集去重与评测集隔离

训练内去重改变“看多少遍”；训练/评估去污染保护“指标可信”。两者规则和目标不同。

EXACT DEDUP

哈希完全相同的文档

成本低，能清理站点镜像与重复抓取；无法识别轻微改写的近重复。

NEAR DEDUP

MinHash / LSH / n-gram 相似

识别模板页、转载与局部重复。阈值过松会误删相似但不同的事实文本。

SEMANTIC DEDUP

向量近邻聚类

更强但更贵，也可能把“同主题但不同答案”聚掉。需抽样验证误删。

DECONTAMINATION

训练集 vs 评测集重叠扫描

至少做精确哈希、长 n-gram 与改写近邻；测试集和训练数据要隔离到版本级。

同一条训练样本反复出现，等价于隐式加权。去重会调整数据分布、重复次数和 token 预算。必须记录去重规则与各来源损失。

05 / CURATION OPERATIONS

现代训练语料的清洗，实际在处理什么？

这是一条可审计的生产流水线。规则、模型过滤与人工抽查各有职责，流程需要固定每一步的判断标准与版本。

步骤实际操作应保留的证据误伤与边界
采集与来源登记记录文档来源、抓取时间、格式、许可/使用条件、内容 hash 与版本；保留原始快照。来源清单、数据版本、解析失败率、文档/字节数。网页正文、附件、代码和论坛对话需要各自的解析与样本规则。
解析与规范化HTML 正文抽取，去导航/广告模板；编码修复、Unicode 处理、OCR；保留代码缩进、数学和表格结构。原始到清洗文档映射、解析器版本、字符/段落变化。不可逆改写可能损伤事实或语法。OCR 错字不应被误认为可信原文。
启发式过滤检查长度、重复行/字符、异常符号、模板占比、语言概率、垃圾页模式。每条规则的拒绝原因与分语言/来源保留率。代码和数学天然符号多；少数语言可能被通用语言检测器误杀。
模型质量筛选分类器、教育价值/相关性评分、困惑度等 proxy；有时用教师标注小集再训练便宜过滤器。标注标准、评分器 revision、阈值、抽样人工一致性。低 perplexity 可能来自模板或重复；事实正确性需要额外核验。
敏感字段处理用规则/识别器定位个人信息、凭据、异常内容，按数据用途决定删除、遮蔽或隔离。策略版本、命中类型、抽查误报与漏报。技术文档示例与真实秘密不同；规则需要语境与权限约束。
去重与聚类规范化 hash 精确去重；n-gram shingles + MinHash/LSH 找近重复；必要时语义检索再核验。重复簇、保留代表、阈值、跨来源/时间重合。LSH 用来发现候选，随后需核验内容是否重复；按重复簇拆分可减少 train/test 泄漏。
评测隔离已知 benchmark 的题目/答案/解题片段匹配、时间/来源隔离、保留污染报告。重叠策略、命中样本、评测集版本。去污染扫描不能证明没有任何改写或未知测试污染；测试内容也不能拿去指导训练标签。
混合、分词与打包按 token 和领域设混合权重/重复上限；锁定 tokenizer，按样本边界 pack/shard 并校验。唯一/总 token、长度分布、重复次数、manifest、有效 loss token。记录清洗后的分布与采样权重，评估其对模型的影响。

处理顺序可按成本和数据特点安排：先做便宜规则可节省昂贵评分，先聚类可避免反复给重复内容打分；多步过滤会相互影响，因此需要保存可回溯的中间统计。分布式数据任务通常按 shard 做确定性转换与校验，失败重跑也要保证同一文档不会重复进入预算。

07 / MEASURE THE RECIPE

怎么判断这次清洗真的有用？

先抽样检查误删/漏删，再比较配方的训练结果。在同 token 或同 compute 预算下，保留原配方基线，逐项加入过滤器并评估 held-out loss、领域任务和长尾切片。每次改变规则都会改变训练分布，不能仅凭平均质量分升高下结论。

同时看被删掉的少数语言、代码、长文本和困难样本。过滤器的高分数据如果高度同质，模型可能更擅长常见格式却失去覆盖。FineWeb 这类公开工作值得学的是数据处理与消融证据的组织方式，具体阈值应按自己的数据分布校准。

08 / OPTIMIZE THE MIXTURE

留下的数据，各自学多少才合适？

例如预算 100B token，代码占 20%，代码唯一储备 5B，则期望处理 20B 代码 token，平均相当于四遍。提高代码占比也可能只是多重复同一小部分样本，相应能力收益要单独评估。长度、质量、去重与来源子群的覆盖要同时记录。

手工混合通常从业务和覆盖约束起步：保留语言/领域底线、设重复上限、按质量分层，再用小规模训练比较配方。课程学习还会改变顺序；先易后难、阶段性长上下文或末期高质量数据的收益都需验证，可通过固定预算的训练消融检验。

先分析高 loss 的来源

来源可能本身难预测、噪声多或 tokenizer 不利。要区分可学习的欠拟合、不可约难度和数据错误；盲目追逐高 loss 可能把预算浪费在噪声。

DoReMi 提供一种实验路线

用小 reference 与 proxy model，基于相对 reference 的 excess loss 做域重加权，再把得到的 token 混合权重用于较大模型。权重来自代理训练中的域损失，迁移到目标规模后还需验证业务表现。

Proxy 的预测要再确认

小模型可能缺少大模型已具备的能力，最优权重也会随 token 预算改变。用中间规模、同 tokenizer 与相近优化条件复核，确认配方是否仍有收益。

避免把验证集训练进去

混合权重本身是超参数。反复据某个验证集选配方会间接适应它；需要保留独立测试、跨来源切片与污染证据。

比较配方时固定什么另外记录什么防止什么误归因
训练 token 或 FLOPs 预算有效监督 token、唯一量与重复次数。数据过滤导致量变了，却把多训练/少训练当质量变化。
模型与合理调参协议初始化、LR/schedule、batch、precision、随机种子。配方收益实际上来自优化配置变化。
评估协议与切片主任务、长尾、语言、长度、恢复/停止行为。平均值变好但某个关键群体退化。
案例：质量分更高但覆盖退化超参数与规模迁移长上下文训练
09 / DATA INTEGRITY

投毒、评测污染与错误数据分别怎样进入系统？

问题进入位置可能影响检查方向
错误或低质标注训练样本与偏好标签。学到错误事实、行为或比较标准。标注规范、抽样复核、来源切片、分歧处理。
训练数据投毒有意设计的恶意训练样本。使参数学到攻击者期望的行为或触发模式。来源与版本追溯、异常簇检查、行为对照和训练后回归。
评测污染评测题目、答案、参考解或相关变体进入训练/选参。评估独立性下降，泛化估计失真。来源/题族/时间隔离、去重、隐藏测试与公开基准外验证。
间接提示注入推理时检索文档或工具结果中的恶意指令。让本次运行偏离授权目标。指令与数据分离、最小权限、动作校验和审计。

Anthropic、英国 AISI 与 Alan Turing Institute 的 2025 年研究，在 600M–13B 模型和特定低风险后门目标下观察到少量恶意文档的影响。这说明平均质量或数据占比不足以排除局部异常；结果不能直接推广到任意前沿规模、攻击行为或防御设置。

治理需要数据清单、来源权限、处理版本和可回溯样本。发现异常时定位受影响数据与 checkpoint，检查正常行为和目标异常，再决定重训或修复范围。来源可信、过滤分高、去重完成分别提供部分证据，仍需组合行为测试。
