ENGINEERING EXTENSION / EVALUATION

模型评估：指标、泛化与发布判断

训练 loss 只说明训练分布上的预测变好。是否可发布，还要看 held-out 指标、切片、生成样例、污染、 统计不确定性和服务成本。评估设计本身就是一个工程系统。

评估的第一原则

先定义决策：要决定是否换模型、是否上线、是否接受一次数据混合改动。根据决策选择指标、比较基线和测试样本。

按任务选择评估指标

切换任务，查看主指标、必须拆的切片、最容易被单一分数掩盖的问题。

NEXT-TOKEN OBJECTIVE

报告 bits/token 或 bits/byte 时要说明 tokenizer；perplexity 在同一 tokenizer/数据切分下可比较，跨 tokenizer 不能直接横向比。

主指标

held-out bits/byte、领域任务、长上下文、多语言

必须切片

语言、领域、长度、训练阶段、重复度

隐蔽问题

测试集污染、tokenizer 改变、训练数据重复导致的记忆

02

几个你会实际写进评估脚本的指标

每个指标关注不同结果，使用前先确定它衡量的对象与计分规则。

CLASSIFICATION

Precision / Recall / F1

\begin{aligned}P&=\frac{\mathrm{TP}}{\mathrm{TP}+\mathrm{FP}},\\R&=\frac{\mathrm{TP}}{\mathrm{TP}+\mathrm{FN}},\\F_1&=\frac{2PR}{P+R}.\end{aligned}

只看 accuracy 会在类别不均衡时失真。明确正类、拒绝类与业务代价。

RETRIEVAL

Recall@k / MRR / nDCG

\operatorname{Recall}@k=\frac{|\mathcal R\cap\operatorname{Top}_k|}{|\mathcal R|}

R 是标注相关文档集合。Recall 衡量候选覆盖，MRR 看第一个正确结果，nDCG 还能区分排序位置与相关程度。无相关标注、分母为零的 query 需声明评估处理方式。

GENERATION

Pass@k / rubric / pairwise

\widehat{\operatorname{pass}@k}=1-\frac{\binom{n-c}{k}}{\binom nk}

每题生成 n ≥ k 个候选，c 个通过，按题估计 k 次采样至少一次成功的概率后取平均；n−c < k 时值为 1。固定采样协议、token/工具预算与验证器，增大 k 会增加尝试次数；单次回答质量和从候选中选出正确答案的能力需分别评价。

LANGUAGE MODEL

bits/token 与 bits/byte

\operatorname{BPB}=\frac{\operatorname{NLL}}{\ln 2\;\cdot\;N_{\mathrm{bytes}}}

NLL 使用自然对数；bits/token 则除以 token 数。BPB 提供共同字节单位，但要固定原文、规范化、上下文窗口与特殊 token 的计分规则。token ID 必须与模型权重匹配，更换 tokenizer 需要相应的模型适配。

04

怎样判断指标差异是否可靠

同一套评估重复跑，结果也会波动；不同模型要尽量做配对比较。

SEEDS

跑多个 seed

数据顺序、初始化和 dropout（若使用）都会变。以均值和波动范围支持模型选择。

CI

给差值置信区间

逐题成对重采样，观察新旧模型的分数差；同文档、多轮会话等相关样本应按组重采样。单个成功率可用 Wilson 区间；只看两条独立区间是否重叠不足以判断差异。

PAIRED

在相同样本上比较

新旧模型逐题对比，记录赢、输、平及各自对应的样本。

ABLATION

一次只改一个关键变量

同时换数据、tokenizer、学习率和池化，无法知道是谁带来了提升或退化。

05

检查训练数据与评测数据的重叠

训练集包含验证题、训练数据的固定模板、或 judge 与训练偏好同源，都能让指标失去独立性。

EXACT原题/原答案哈希重叠

至少用规范化后的精确匹配检查。

N-GRAM长片段重叠

识别轻微模板改写；阈值要抽样验证。

SEMANTIC语义近邻重叠

跨语言/改写污染更隐蔽，但成本更高。

JUDGE评估器与训练偏好同源

偏好数据、奖励模型和 judge 需要独立证据，避免闭环自我强化。

报告时写清楚：测试集版本、去污染方法、是否按切片去重、是否只在训练后一次性使用。没有这些信息的分数很难复现，也很难信任。

06

一个可执行的发布门槛

把必须满足的质量底线写成发布条件，再比较主指标和资源成本。

01

正确性与安全底线

硬失败集、拒绝策略、隐私/工具调用风险必须通过。

02

目标内提升有区间

主指标跨 seed/切片提升，差异有置信区间或成对证据。

03

邻近任务未越过回归线

语言、长度、领域、检索、生成质量都在允许范围内。

04

系统成本可接受

延迟、显存、索引更新、部署版本与回滚路径全部验证。

小模型学习与泛化实验保留独立组合和长度外推的逐题预测，分别显示 teacher-forced loss、自由生成 token accuracy 与完整序列 exact match。

07 / GENERALIZATION

怎样判断“训练好了”，又怎样判断泛化？

这里有三个决策：优化是否有效、是否值得继续投入，以及是否满足使用要求。

数据 / 阶段用途能支持的结论评估范围与限制
训练集计算梯度、拟合参数。目标能否被优化、数据/数值/标签是否明显异常。未见输入的表现和样本记忆情况，需要另外设计测试。
验证集选 checkpoint、超参数、数据混合和停止时机。在这个验证分布上的模型选择证据。反复选参会间接拟合验证集，不能始终当作独立最终测验。
锁定测试集方案确定后做独立比较。在指定分布、采样协议与样本量下的泛化估计。结论限于已测分布；污染扫描仍可能漏掉重叠。
分布外/时间切分新领域、新模板、后来的事件、未见组合、长尾条件。针对这些变化的迁移与鲁棒性。逐类报告分布变化，例如新领域、新模板或新时间段。
上线与回归真实任务、环境状态、成本和用户分布。当前使用条件下的可靠性与漂移证据。离线分数不自动等于线上成功率。

评估泛化时，要检查训练与测试之间更广泛的关联。近重复、相同模板、同一文档不同段落、同一道题的改写都可能泄漏。根据要验证的能力，按文档、来源、实体、题族、仓库或时间做分组划分，再核对污染与相关样本。

一个模型可以在训练 loss 继续下降时，验证或目标任务已经停滞。反过来，预训练中不一定等到经典“训练集下降、验证集上升”的过拟合形状才停止：固定预算、边际收益、学习率日程、下游质量和服务成本都会决定终点。

08 / STOPPING & RELEASE

把“训练好了”改写成可执行的判断

数值闭环通过

有效标签、mask、梯度、参数更新、保存恢复都正确；小样本可拟合。完成这一步后，再做独立任务测试和发布评估。

验证改善有可信收益

与基线配对比较主指标与切片，报告样本量和区间。预先决定最小实际收益、允许退化幅度与最大预算，避免拿单次噪声峰值选模型。

继续投入是否划算

验证曲线的改善速度、成本/有效 token、目标任务收益、失败集与 LR 阶段一起看。early stopping 的 patience/min_delta 要符合评估噪声和频率，不能照抄常数。

发布门槛满足

独立测试、目标任务、长尾回归、输出协议、延迟和恢复路径均满足约定。后训练 reward、CoT 长度和 perplexity 可作为辅助观测，与这些发布条件一起分析。

怎么区分记忆、模式匹配与可迁移能力？

没有一次实验能完美分离。可通过同题改数字/条件、未见组合、跨来源测试、时间后移、去掉无关提示和对抗反例寻找证据；同时控制难度变化。把失败样本归因到知识缺失、感知错误、推理、工具、检索与协议，才能选择后续探索方向。

Loss、能力、泛化为什么可能不同步？

平均 token loss 对所有预测位置加权，任务评分常只看最终答案。少量关键 token 的改进、答案阈值、采样策略和测试难度会使任务分数出现不同形状。模型在一项能力上提高也可能伤害另一项；因此要同时看分布指标和目标任务。

09 / REPEATED TASKS

试很多次能成功，和每次都可靠，分别怎样测？

探索型任务可能允许多次尝试后选一个结果；自动执行任务则常要求每次都遵守约束。记录单次 trial、完整轨迹和最终环境状态，再按决策选择“至少成功一次”或“重复执行全部成功”的指标。多候选还需要选择器，任务重复成功也要检查副作用。

重复成功率对照

独立同分布的概率示意
至少成功一次
每次都成功

真实执行存在共同故障：相同工具不可用、同类题目超出能力、环境状态污染。直接把平均成功率代入独立公式会掩盖题目差异和相关性。应保存逐题多次结果，按题族或环境分组给区间，报告 timeout、基础设施失败与模型失败的分类规则。

比较固定什么变化什么报告内容
模型贡献任务、运行系统、工具、预算、判分器。模型 revision。完整任务成功、约束违反、成本、失败切片。
运行系统贡献模型、任务和判分器。规划、重试、上下文压缩、工具接口。质量变化和额外 token、工具调用、延迟。
交互效应同一任务矩阵。模型 A/B × 系统 A/B 的四种组合。哪些模型收益依赖特定系统；不能直接归因给单个部件。

工程依据：Anthropic《Demystifying evals for AI agents》（2026-01-09）。环境应隔离、可重置，超时和重试预算与结果一起保存。

10 / GRADER ERROR

判分器给出的通过率，偏差从哪里来？

LLM judge 的评分需要用人工复核或可执行证据校准。规则判分器也可能漏掉等价答案、未覆盖的错误或隐藏副作用。先建立明确 rubric 与复核样本，再分别统计把正确判错、把错误判对的比例。

假设总体比例 · 非某个 judge 实测
观察通过率
相对真实率偏差
结果类别总体占比

对分歧样本做复核

按任务、长度、语言与输出风格采样。位置偏差可通过交换 A/B 顺序检查；格式与措辞偏好可用保持内容不变的改写检查。rubric 与 judge 版本一起保存。

公开测试逐渐进入训练循环

题目被讨论、改写、合成后，精确匹配也可能查不到关联。保留时间后移、私有题族和环境变化的测试；反复据测试结果调参会消耗其独立性。

把校准误差带入结论

judge 的敏感度/特异度可能随新模型风格改变。不能假定新旧模型共享同一误差；除了分数区间，还要检查判分分歧和错误类型。

记录预算与选择过程

模型、运行系统、采样参数、工具权限、候选数、最大时间和成本共同定义测试条件。每次挑最好的结果会改变成功率的含义。
