03 / FORWARD NUMERICAL FAILURE
相同 softmax 目标，为什么 naive exp 先溢出？

    
    
本案例在指定 batch 的输出头后加入共同的 +128 刺激。模型输出和加法结果仍有限；直接 exp 会产生 +∞，求和仍为 +∞，随后的 ∞／∞ 得到 NaN。日志单独记录 loss.shifted_logits、loss.exp、分母、概率、log 概率和目标选择，首个异常取自真实有限性统计。
修复和稳定参考使用 log_softmax 的稳定表达式，从相同的平移后 logits 求目标 NLL。实际 loss 从保存 logits 与 labels 独立重算，并与共享 core 的未平移 CE 比较，容差公开记录。共同的安全规则在 loss／梯度非有限时跳过更新，所以故障的下一次前向可以仍有限；跳步不会恢复基线本来应执行的更新。

    
  


  

    
04 / FINITE UPDATE FAILURE
过大的 LR 可以让所有张量有限，但轨迹已经偏离

    
第二个案例保持 logits、loss 和梯度不变，只在 optimizer.step() 前把 AdamW LR 从 0.003 改为 0.6。报告测量真实的参数位移，随后用更新后的模型和实际下一 batch 执行前向。当前保存结果出现大幅有限更新和下一前向分歧，日志按观察结果显示有限性。

    
    
修复在相同更新前快照加载完成后恢复约定 LR；比较 loss、梯度、更新后参数、下一前向和完整 optimizer／RNG／cursor 状态。仅把幅度裁小不能代替该检查，因为裁剪会改变更新方向或大小。本例不把参数变大直接称为 NaN，也不从单步现象推断长期收敛。

  


  

    
05 / FINITE SEMANTIC FAILURE
标签合法、loss 可能更小，目标仍然错误

    
第三个案例在有效答案位置执行 A→B→C→D→A 的符号 ID 轮换。输入和 teacher-forced 历史保持原记录，EOS 不改，−100 位置不改，监督 token 数完全相同。轮换后的标签都在合法词表范围；所有激活、loss 和梯度可以保持有限。
同一 logits 分别计算实际错误标签的 loss 与正确标签 loss，量化两者差值及全参数梯度差的 L2、相对 L2 和最大元素差。错误目标的 loss 可能更小，这不能说明原任务变好；完整标签对照和反转规则提供语义证据。修复必须恢复正确 labels，并从相同更新前状态重跑，不能在已经被错误目标更新过的参数上声称恢复了原轨迹。

    
  


  

    
06 / DIAGNOSTIC SCOPE
hooks 与 anomaly detection 能定位到什么范围？

    
“首个”依赖监控集合
模块输出 hooks 在模块前向完成后执行，包含各 block 返回元组的 hidden／KV；损失中的关键操作另行显式记录。SDPA、GELU 内部所有 kernel 张量未被逐一记录，因此结论是监控集合中的首个异常。
反向顺序来自实际回调
Tensor gradient hooks 在梯度计算时记录。参数 hook 的顺序来自 autograd，本页不按前向层名反转来伪造反向顺序；同一输出的别名只挂一次梯度 hook。
anomaly probe 是单独诊断回放
PyTorch 2.9 的 detect_anomaly(check_nan=True) 可对失败反向给出关联前向 traceback，并在反向 NaN 时抛错。指数案例同时保留普通 trace 和定向 probe，后者可提前中止，因此不能替代完整传播记录。
高 LR probe 的具体边界
本页 high-LR probe 只重跑更新前前向和反向，没有执行 high-LR optimizer 更新或下一前向。它没有抛错，只说明这段反向有限；高 LR 后果由主实验的真实更新和下一前向测量。

    
标签 probe 的有限反向不会验证监督语义。诊断 hooks 有额外开销，本页不报告性能；逐位恢复一致性只在记录的软件和 CPU 环境内核验。导入文件的字符串安全显示，不执行 HTML，也不由浏览器读取或反序列化 .pt。
