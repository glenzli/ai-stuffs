03 / POST-TRAINING

后训练：表示、生成与偏好目标

“继续微调”可能是在重塑句向量几何，也可能是在模仿回答格式、学习偏好排序，或让小模型模仿大模型。 它们都仍然使用梯度，但训练数据的组织、loss 和被优化的对象不同。

先分层

预训练先让模型获得通用能力；后训练再用更窄的目标改变表示、行为或输出排序。各类方法使用的监督数据和损失不同，下面逐项展开。

02

表示后训练、SFT、偏好对齐：
各自怎样提供监督？

对照监督数据、损失函数和梯度路径，可以看清这些方法各自优化什么。

表示层 Retrieval fine-tuning

把“该近 / 该远”的行为写进句向量

数据是 query、positive、hard negative。InfoNCE 直接把语义检索的排序误差传回编码器，让向量空间更适合你的任务。

loss = CE(q @ dᵀ, positive_idx)
  • 直接关心 embedding geometry
  • 可能冻结 backbone，只训练投影/Adapter
  • 常见风险：负样本错、领域偏移、其他任务退化
行为层 Instruction SFT

用示范回答，改变下一 token 的分布

数据是 prompt 与示范 response。这里采用常见的 response-only 交叉熵，直接监督回答部分；全序列 SFT 也存在。prompt 虽不直接计 loss，仍作为上下文参与计算。

loss = -Σ log p(responseₜ | prompt, response<ₜ)
  • 直接关心回答格式与示范行为
  • 不保证本征句向量最适合检索
  • 常见风险：模仿表面风格、记数据、不会拒绝
偏好层 RLHF / DPO

根据回答之间的偏好训练策略

数据是 prompt 下的 chosen vs rejected。DPO 优化策略相对 reference 模型的对数概率优势；RLHF 常先训练 reward model，再优化策略。

提高 chosen 相对 rejected 的 log πθ - log πref
  • 直接关心回答的相对排序
  • 可编码有用性、安全偏好等主观约束
  • 常见风险：奖励钻空子、过度拒绝、偏好偏差

为什么 SFT 也可能“改 embedding”？ 因为它会更新同一网络里的权重，表示也会变化。SFT 直接优化回答 token 的概率，query-document 排序则可能改善或退化，需要单独做检索评估。

easy negative

随机负例

如无关的咖啡店段落。能防止明显坍缩，但模型很快学会区分，梯度信息有限。

hard negative

难负例

共享关键词、主题相近，但不含答案。最能改变细粒度决策边界，也最需要可靠判定。

false negative

假负例

被标为负例的段落也可能满足任务要求。这样的漏标会让训练压低有效证据的分数。

04

一个 base model，为什么要做出不同接口？

后训练目标、输出头和使用协议共同决定模型对外提供的接口。

01Embedding API

编码一段文本，输出固定或可变长度的向量。关注批次、最大长度、输入指令、池化、归一化和维度。

text → vector
02Cross-encoder reranker

同时读 query 与候选，输出相关性分数。更准但每个候选都要一次前向，不能提前编码全库。

(query, passage) → score
03Causal LM

输入前文，输出下一 token 分布。将隐藏状态用于句向量时，需另外验证读出方式与检索效果。

text → token probabilities
04Classifier / task head

在 pooled representation 上接分类头，分类目标促进类别可分；检索效果需按检索任务另行测试。

text → label distribution
05

后训练后的回归评估

评估目标任务的收益，同时检查其他语言、长度、领域和服务指标的变化。

01

目标内提升

检索 Recall@k、MRR；聚类；分类 F1。先确认你想优化的主指标真的动了。

02

邻近任务回归

语义相似、重复检测、其他语言、短/长文本。避免“只对训练数据分布有效”。

03

系统成本

维度、索引内存、编码吞吐、batch 延迟。embedding 不只有质量，也有服务边界。

04

版本与漂移

模型、chunk、normalize、指令前缀任一改变都可能让新 query 与旧索引不可比，需要重建。
