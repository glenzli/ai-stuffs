固定 microbatch 和消费样本总数时，增大 accumulation 会减少 optimizer 更新次数；每次更新要累积更多轮 forward/backward。通信不会自动减少：标准 DDP 默认在每轮反向同步，需在前 A−1 个 microstep 用 no_sync 覆盖 forward 和 backward，最后一轮再同步。显存与吞吐收益取决于保存激活、通信和调度方式。

04

多卡训练的几种分工方式

不同并行方式切的是不同维度；大规模训练通常组合 DP、TP、PP 和序列并行。

DATA PARALLEL

复制模型，切 batch

每卡处理不同样本，反向同步梯度。实现简单、吞吐高，但每卡必须放得下完整训练状态。

all-reduce gradients
ZeRO / FSDP

切参数、梯度、优化器状态

训练状态分片保存，计算所需的参数在使用前重聚。省显存，代价是更多 all-gather / reduce-scatter。

shard → gather → compute → reshard
TENSOR PARALLEL

切单层矩阵计算

把 attention / MLP 的权重和计算按维度拆到多卡，层内需要高频通信。适合单卡装不下单层或需要更多 compute 并行。

layer-level sharding
PIPELINE PARALLEL

切模型层，流水线送 batch

不同 GPU 负责不同层；需要 micro-batch 填充流水线，并处理 bubble、激活缓存和跨阶段通信。

stage 1 → stage 2 → …

显存、吞吐和收敛是三个指标。分片可能让你“跑得起来”，但通信会压低吞吐；增大全局 batch 可能提高并行效率，却改变学习率、训练 token 预算与泛化行为。配置选择应同时比较内存、速度和训练效果。

05

从代码到可信 checkpoint 的操作顺序

从小规模验证开始，再逐步扩大计算量和并行规模。

01

单 batch 过拟合

用极小数据确认 tokenizer、loss、mask、反传与 checkpoint 能闭环；loss 应能明显下降。

02

代表性数据小跑

测真实长度分布、吞吐和显存峰值。记录 tokens/s、step time、grad norm、dataloader wait。

03

扩大并行与 batch

逐级增加 GPU/accum；先确认数值等价或可解释差异，再追求吞吐。检查通信和 checkpoint 写入瓶颈。

04

定期评估与放行

目标指标 + 邻近任务 + 生成样例 + 失败集。只有证据通过，才让新 checkpoint 进入下游或重建索引。

06

训练事故的排查顺序

下面按症状列出观测信号和排查步骤，结合数据、梯度、运行状态与评估结果定位。

GPU 利用率周期性掉到 0

先看 dataloader wait、共享存储吞吐、worker 数与 shard 大小。常见原因是 CPU tokenization 在训练时才做、每步去读小文件、batch 预处理不同步。把清洗和 tokenization 离线化、预取 shard、固定长度/bucket 往往比换 GPU kernel 更有效。

loss 突然尖峰或变成 NaN

同时看 raw loss、grad_norm、学习率、被跳过的 optimizer step、混合精度溢出。检查数据 shard 是否损坏、长度是否异常、attention mask 是否正确、是否需要 bf16/fp16 loss scaling、梯度裁剪与 warmup。先定位发生在哪个 step 和哪条数据，再谈修模型。

OOM 发生在第 3 个 microbatch

activation 会额外占用显存。看峰值是否随 T、microbatch 或图像/文档长度增长；尝试 activation checkpointing、序列 bucket、减少 microbatch、增加 accumulation，或换 ZeRO/FSDP。先用 profiler 区分参数、activation 和碎片。

单卡 loss 正常，多卡反而变差

比较全局 batch、学习率、warmup、gradient accumulation 与数据分片。检查 all-reduce 是否在正确时机发生、样本是否被重复或漏读、随机种子是否在同一 rank 重复。扩大 batch 往往要重新调学习率和训练预算。

SFT 生成效果差，但 token loss 下降

token CE 衡量“在参考答案前文下预测下一个 token”，不等于端到端生成质量。检查 chat template、EOS、assistant mask、推理 stopping、packing 泄漏和是否对长答案过度加权；加 heldout 生成评测与人工样例。

后训练后检索指标下降

先确认你拿的是同一个 embedding 接口：pooling、projection、normalize、instruction prefix 是否变。再检查 SFT 数据是否改变了表示、后训练目标是否与检索一致、索引是否用新模型重建。查询向量和文档索引应采用兼容的模型与编码协议。

一次实验需要保存哪些“证据”？

复现实验需要同时保存随机状态、数据顺序和运行配置。

DATAtokenizer hash

词表、normalization、特殊 token 和模板版本。

DATAshard + order

训练数据版本、去重结果、随机顺序与采样权重。

MODELconfig + init

层数、宽度、位置编码、权重绑定和初始化来源。

RUNoptimizer + schedule

学习率、warmup、grad clip、batch、accumulation、精度。

SYSTEMparallel + kernels

DP/ZeRO/TP/PP、通信后端、flash attention 与编译选项。

EVALmetrics + samples

验证集版本、指标、失败样本与人工审阅记录。

SAVEcheckpoint bundle

模型、优化器、scheduler、RNG、数据游标与恢复验证。

SERVEexport + index

合并 LoRA、精度转换、归一化方式、索引版本与回滚点。
