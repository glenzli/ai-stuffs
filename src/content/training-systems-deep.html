训练系统：分片、精度与通信

参数、梯度、优化器、激活、层、专家和序列都可以被切分，但每一种切法换来不同的 collective、内存和调度。 精度又决定每份状态占多少 bytes。下面按切分对象和通信方式逐项分析。

并行方式与切分对象

DP 切 batch，ZeRO/FSDP 切训练状态，TP 切层内矩阵，PP 切层，EP 切专家，CP 切序列。一个真实训练通常是组合方案。

01

沿哪个维度切？

切换一种并行方式，看权重、梯度、优化器、activation 与 batch 分布怎样变化。

DATA PARALLEL

复制完整模型，让不同 GPU 算不同 batch

每卡有完整权重、梯度和优化器状态，适合单卡放得下训练状态的情况。梯度用 all-reduce 同步；DDP 可在梯度桶就绪后发起通信，与反向计算重叠。

可以避免显式保存完整 T×T 矩阵，显存更接近随 B·T·d 线性增长；但反向仍需保存/重算部分中间量，通信与 kernel 支持也会影响结果。

计数假设 MHA 的 Q/K/V 都有 H 个头，模型宽度为 H×head dim；元素数分别为 BH T²、3BT H·head dim、2BTF 和 BT H·head dim，再乘每元素字节数。gate/up 只数两路投影，不含 SiLU、逐元素乘积或 down projection 的额外中间量。面板不是反传保存清单或总峰值；GQA、融合算子、重算、临时 workspace 与通信缓冲需另算。FP8 选项仅按 1 byte 计数，不表示这些张量都能使用 FP8 kernel，也未计缩放元数据。

04

四个 collective，先认清再调并行

集合通信会占用带宽并造成等待，需要放进完整执行时间线分析。

ALL-REDUCE

每卡算出局部贡献，求和后人人得到完整结果

典型用于 DP 梯度同步。通信量与模型梯度大小相关，可用 bucket/overlap 与 backward 重叠。

g = Σ_i g_i
REDUCE-SCATTER

规约并只保留自己负责的分片

ZeRO/FSDP 常用来规约梯度并保留本卡分片，再更新本卡拥有的优化器状态；Adam 的 m/v 按各自参数分片维护。计算所需的参数分片之后还可能需要 all-gather。

reduce → shard
ALL-GATHER

把各卡的分片拼成完整张量

ZeRO-3/FSDP 计算层前重聚参数，TP 也常用。频繁 gather 会把参数分片省下的显存换成带宽压力。

shards → full
ALL-TO-ALL

不同 token 发给不同专家/设备

MoE expert parallel 的核心通信。路由不均衡时，某些设备成为热点；需要容量、负载均衡与调度。

tokens ↔ experts
05 / PIPELINE SCHEDULE

每张卡何时前向、何时反向？

Pipeline Parallel 将层分给不同阶段，再把 batch 拆成 microbatch。后阶段等待前阶段的激活，前阶段的反向等待后阶段的梯度。调度改变空闲位置和激活保留时间；本例所有 microbatch 完成反向后才更新权重。

GPipe 与 1F1B 时间线

每次前向/反向各 1 tick，通信时间为 0

依赖操作必须在前一 tick 完成；每个阶段每 tick 至多执行一项。GPipe 采用全前向屏障，1F1B 采用 warmup、交替和 cooldown。

F/B 后数字为 microbatch 编号。激活以每阶段、每 microbatch 一份计数，反向结束后释放；不含张量尺寸、重算和传输缓冲。逻辑 tick 不预测真实时延。

1F1B 可让已完成前向的激活更早被反向消费，通常能降低某些阶段的保留峰值；在本例同速、零通信假设下，完成时间未必比 GPipe 更短。实际模型阶段耗时不等，通信、重算、虚拟阶段和调度交错都会改变结果。

Microbatch 增多可以更充分填充流水线，但同时改变每次更新的样本组织。比较必须保持全局目标、梯度缩放与权重版本语义一致。异步更新或不同版本权重属于另一类协议，不能直接套用本例的同权重对照。

CASE / OVERLAP WITH DEPENDENCIES

DualPipe：哪些通信能被覆盖，哪些依赖仍要等待？

DeepSeek-V3 的 DualPipe 将前向/反向 chunk 细分为 Attention、专家分派、MLP 与合并；反向再分输入梯度与权重梯度，并用双向流水线和计算—通信重叠改善执行。原报告还给出参数副本与激活的代价；这些条件不能从一个“并行”标签里省略。

为什么可以在这个教具里称为“最短”？

每个不抢占、同通道互斥的可行调度，都给出一份计算顺序和一份通信顺序。把顺序边加入原依赖后，必须无环；对固定顺序，各节点按前驱最晚完成时刻启动，不会比同顺序的其他方案更晚。因此枚举所有通道顺序并取最小值，覆盖了本模型的所有可行完成时间。

激活峰值限 1 另要求所有旧反向计算完成后才能开始 FA。因为它们和 FA 都使用计算通道，该条件等价于相应操作全部排在 FA 之前；枚举中保留这些顺序即可。证明只用于本例的两份激活包规则，没有推广到细粒度张量释放或真实 GPU 调度。

把激活存活规则也写进比较

只计两份逻辑激活包：旧反向包在 t=0 已存在，全部旧反向计算完成后才释放；新前向包在 FA 开始时取得，并留到本对 chunk 之后。相同时刻先释放再取得。该粒度故意简化，不含张量大小、逐层释放、重算、参数副本或通信缓冲。

06 / PARAMETER LIFETIME

参数分片之后，完整参数何时出现？

每卡长期保存一部分参数，计算一层时临时聚齐该层。前向后释放完整参数能降低存活量，反向则需要重新获取。把状态分片和计算时的临时缓冲区放在同一条时间线上，才能解释峰值。

本例用两个 DP rank、两层 2×2 矩阵和 tanh 中间激活；每卡持有不同样本。每层按扁平数组分成两个连续片段。目标是两份 ½‖Y−target‖² 的平均；反向先产生本地完整梯度，再求和、除以 2 并保留本卡片段。
