ARCHITECTURE / VARIANTS & CONCLUSIONS

架构变体：逐项比较结构与成本

现代 decoder 可以看成几个可替换零件的组合：Attention / KV 结构、位置编码、归一化、FFN 激活、 残差布局和 Dense/MoE。每个选择通常优化一个资源或能力，同时在其他地方付出代价。

先定判据

先选比较口径：同训练 FLOPs、同激活参数，还是同推理延迟；这些约束未必能同时固定。记录未控制的差异，再固定数据与评估协议，才好判断结构收益。

各类变体的结构、收益与代价

选择一项变体。重点看结构改了什么、改善了哪项指标，以及结论适用于哪些条件。

STANDARD ATTENTION

每个 query head 都有独立 K/V

每个 query head 拥有自己的 K/V projection。固定 batch、序列长度、层数、query heads、head dim 和存储精度时，MHA 的 KV 缓存不小于共享 KV 的 GQA/MQA；结构本身不保证任务质量更高。

结构变化 Hq = Hkv; cache ∝ Hkv · D
获得

每个 query head 有独立的 K/V 投影。

代价

固定其他维度时缓存通常更大；实际时延取决于实现与硬件。

评估条件

head 数量的收益需要结合每头维度、训练配方和任务结果评估。

05

结构选择的常见影响

这些是机制层面的结论；具体幅度仍依赖规模、数据和 kernel。

01

Residual + pre-norm 是现代深层的默认底座

残差与 pre-norm 影响梯度和表示的传播。RMSNorm 省去了均值中心化，具体质量收益需要在相同训练配方下做替换实验。

02

GQA/MQA 是 KV 与表达的折中

减少 KV heads 直接压低 decode 带宽与缓存，但共享越激进越依赖训练弥补表达。实际选择看上下文长度、batch 与质量回归线。

03

MoE 用显存和通信换每 token 计算

总参数增大、激活参数可以较小；所有 experts 仍需驻留/可达，router 不均与 all-to-all 是核心风险。

04

长上下文的有效使用范围

位置外推、训练长度、attention 模式、数据与评估都决定模型能否在远端 token 上可靠工作。

05

FlashAttention 优化注意力的执行方式

它通过分块与在线 softmax 降低内存访问，通常仍是同一 attention 数学；评估时分别记录数学目标和执行 kernel。

06

质量同时受结构、数据和预算影响

宽度、深度、FFN、数据、token 预算、位置和推理成本共同作用。比较时先固定预算，否则结论不可迁移。

06 / LONG CONTEXT

长上下文训练需要哪些配合？

01 / POSITIONS

位置机制兼容

检查 RoPE 频率、缩放、插值、滑窗/全局层；新长度下的相位关系改变。

02 / DATA

长程监督有用

长文本应包含需要跨段结合的证据，让模型有机会学习远距离依赖。

03 / TRAIN

预算与稳定性

调整长度混合、microbatch、LR、重算和 context parallel；保持全局有效 token 口径。

04 / VERIFY

长短任务一起测

长度、位置、干扰、检索/组合/聚合与短上下文回归，连同成本和延迟报告。

RoPE 让不同位置的 Q/K 通过旋转表达相对位移。把位置插值进已训练范围，或修改频率尺度，会改变距离与相位关系；这可能帮助扩展，但不能单凭数学变换保证新长度的能力。继续训练的数据、长度课程和原始模型决定是否适应，短距离分辨率也可能受影响。

长度 L 的全注意力算术量含 L² 项；FlashAttention 减少物化中间矩阵与 HBM 搬运，不消除这个交互数。滑窗缩小局部访问，但跨窗口信息如何传播取决于层结构。context parallel 把同一长序列的计算分给设备，仍需要交换相应状态，共同完成这条序列的前向与反向。

评估轴测试变化能回答什么
长度 × 位置固定任务，改变上下文长度、证据放头/中/尾的位置。模型在哪些长度和位置可靠，而非只报告最大可输入长度。
单条检索找一个明确事实或标记，加入相似干扰。能否找到局部信息；不能代表跨多证据推理。
多跳/组合分散多条事实，必须按关系组合才能回答。各条远端证据是否共同影响答案。
聚合/顺序计数、排序、跨段去重、事件先后和矛盾更新。长程任务执行与状态维护；单 needle 命中率不足以覆盖。
成本与短程回归相同任务/推理预算下测显存、TTFT、ITL 与短问题质量。扩展是否值得，以及是否牺牲常见场景。

RULER 用多类合成任务揭示“标称上下文”与实际使用能力之间的差距；合成评估也有范围，应再测真实文档、代码仓库或多轮任务。报告可靠长度时应明确通过阈值、任务类型和位置分布，每个可靠长度结论都应对应到这些评估条件。

CASE / RESIDUAL MIXING

mHC：多条残差流怎样混合，约束又保证到哪里？

普通残差把分支输出加回一条流。Hyper-Connections 扩成多条流，并学习层间的混合。DeepSeek 的 mHC 再约束残差混合矩阵；它改变的是计算图，不能只当成优化器或 KV 压缩技巧。

有限次 Sinkhorn：把误差也留下来

固定正矩阵 M⁽⁰⁾=[[4,1],[1,1]]，交替归一化。本站教具约定每轮先行、后列；原论文 v1 式 9 写的是先列、后行。二者有限次结果不同，不能只凭同为 20 轮就认作逐步复现。

固定线性读出 L=ΣᵢⱼM⁽²⁰⁾ᵢⱼGᵢⱼ，G=[[0.2,−0.3],[0.4,0.8]]。本例从四个原始 Z=log M⁽⁰⁾ 出发，沿 20 轮归一化逐步反传；有限差分核对全部四个导数。一次 η=0.1 的 SGD 后，读出由 0.700000 变为 0.695987。这是指定矩阵目标的更新，不是模型质量提升，也没有实现状态相关的系数预测器。

残差混合不放大，不等于不丢差异或整网都稳定

对精确非负双随机的方阵，二范数至多为 1；这样的矩阵相乘仍满足同样约束。对每个固定输入方向 v，‖Bv‖₂≤‖v‖₂。该结论只约束残差混合算子，不把近似行列和自动升级成精确条件。

07

看到一篇架构论文，怎样判断它在证明什么？

先检查控制变量，再看机制是否解释结果。

同一参数/激活预算？

MoE 的“更大”可能是总参数，也可能只是训练 compute；要区分。

同一训练 token？

多训练本身就能提升质量，与结构改良混在一起。

同一数据和 tokenizer？

词表变化会改变有效序列长度和 bits/byte。

同一推理协议？

batch、context、precision、decoding 参数不同，延迟与质量不可直接比。

有消融还是只有总表？

一次换多个部件时，无法归因到具体设计。

机制和指标一致吗？

声称省 KV，就应报告缓存、带宽和长上下文回归；不能只报训练 loss。
