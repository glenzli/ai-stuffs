MODERN AI / EFFICIENT INFERENCE

量化与投机解码：省什么，付出什么

量化减少数值表示成本；投机解码减少昂贵模型的串行调用。量化通常引入数值误差；投机解码在精确采样条件下可保持目标分布。实际收益取决于 batch、序列长度和硬件。

四张账单

权重存储、激活计算、KV 缓存、端到端时延。使用 INT4 时，还要检查未量化张量的精度和各阶段耗时。

01 / QUANTIZATION

量化把连续数值映射到有限的刻度

量化先选择动态范围和刻度，把值映射成有限整数或低位浮点；计算时使用支持该格式的 kernel，或恢复/转换到其他格式。分组量化为不同 group 保存 scale，能减轻 outlier 对整个张量的影响，但增加元数据和处理成本。

对线性层 y=Wx，权重误差造成 Δy=(Ŵ−W)x。仅比较 ||Ŵ−W|| 不足以说明任务影响，输入激活 x 的分布也重要；这就是校准数据、层敏感性与 activation-aware 方法有意义的原因。

配置减少什么还需要什么额外检查
Weight-only / W4A16权重用低位格式存储，激活保持较高精度。group scale、打包格式、支持的矩阵乘 kernel。计算精度由 kernel 决定；长上下文 KV 占用另行计算。
W8A8 / FP8权重与部分激活的存储、带宽或矩阵乘成本。动态范围管理、scale、累加精度及硬件支持。FP8 使用浮点格式，INT8 使用整数格式；实际收益取决于 kernel。
KV 量化随请求数、序列长度增长的缓存。K/V 校准或动态 scale、解量化与 attention kernel。权重量化后 KV 不会自动变小；长程误差需单独测。
PTQ / QATPTQ 在已有模型上校准/转换；QAT 在训练中暴露量化误差。PTQ 可能重构局部输出；QAT 常用 fake quant 和近似梯度。确认 PTQ 的校准方案，以及 QAT 中前向模拟和反传使用的精度。

04 / SPECULATIVE DECODING

小模型先写草稿，大模型并行验收

draft model 先自回归提出 k 个候选，target model 在一次前向中计算这些位置的条件分布。验收从左到右进行；第一次拒绝后，后续草稿的前缀已经不成立，需要丢弃并修正。这能减少 target 的串行调用，但增加草稿计算、验证工作量和缓存管理。

一次验收回合

预设的拒绝位置，用于展示缓存与前缀

此处按预设状态展示验收过程。精确随机投机采样需要正确的 p/q、残差采样和一致的目标采样规则；argmax 一致只比较了概率最高的候选。量化后的 target 则是另一个目标分布。

什么条件下能节省时间？

draft 足够便宜，接受率高，target 的多位置验证能摊薄权重读取成本。长草稿并非总好，第一次早拒绝会浪费后续工作。

需要测哪些指标？

最终输出分布/质量、接受长度、draft 耗时、验证耗时、吞吐与 p95 延迟。已高度批处理的服务可能收益有限，需要端到端测量。

05 / PROBABILITY MASS

接受的概率质量，加上修正后等于多少？

草稿提出 token v 的概率为 q(v)，其接受概率为 min(1,p(v)/q(v))。两者相乘，直接接受的概率质量就是 min(p(v),q(v))。拒绝后的修正分布补齐剩余的正差。

同一分布允许不同字符串

独立采样的输出可以不同。解析等式核对的是每个输出事件的概率；重复抽样频率只能提供带抽样误差的辅助证据。

多 token 验收逐前缀成立

接受一个位置后，下一位置的条件分布以已确认前缀为条件。首次拒绝后，后续草稿的前缀不再成立，应丢弃对应候选并回滚缓存；全接受时可再从目标分布取一个 token。

06 / TRAIN THE DRAFTER

MTP boosting：骨干定下来后，草稿头还怎样训练？

为什么服务端还要按整个 batch 算，而不是逐请求取最大值？

DSpark §3.2.2 将 R 个请求的长度 ℓᵣ 放在同一账本：B=Σᵣ(1+ℓᵣ) 是送入目标模型的位置数，预计产出 τ̂=Σᵣ(1+Σⱼ≤ℓᵣ Ŝᵣⱼ)，目标为 τ̂·SPS(B)，其中 SPS 是预先测得的每单位时间步数。所有请求共享同一成本曲线，不能各自挑长度后再把吞吐相加。该近似主要以 B 描述成本；真实引擎还应核对上下文、缓存、草稿耗时与延迟约束。

论文的逐步早停并不无条件找到全局最优；还需要目标沿候选路径具有单峰结构。§5.2 明确讨论硬件曲线的离散台阶，以及使用两步前的历史预测确定容量的异步适配。本站固定曲线的枚举不等于实现了该生产调度器。
