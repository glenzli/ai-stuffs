FRONTIER 02 / RL POST-TRAINING

RL 后训练：采样、评分与策略更新

偏好模型、可验证 verifier、rubric 或 AI judge 给出奖励；rollout 产生回答；算法把奖励变成相对优势， 再通过 policy gradient / clipped objective 更新策略。reference、KL 与评估决定它会不会跑偏。

奖励、算法与参考策略

奖励从哪里来、算法如何利用奖励、参考策略如何约束偏离。DPO、PPO 和 GRPO 在数据来源、计算流程和更新目标上各有区别。

03

PPO、GRPO、DPO：优化对象不同

公式都简化成核心项；真实实现要处理 token mask、长度、ratio、reference、value/clipping 与分布式训练。

PPO / RLHF

奖励 + 价值基线 + 裁剪策略更新

\begin{gathered} \max_\theta J_{\mathrm{clip}}-\beta D_{\mathrm{KL}},\\ J_{\mathrm{clip}}=\mathbb E\!\left[\min\!\left(\rho_t A_t,\operatorname{clip}(\rho_t,1-\epsilon,1+\epsilon)A_t\right)\right]. \end{gathered}

ρₜ = πθ(aₜ|sₜ) / πold(aₜ|sₜ) 表示新旧策略的动作概率比。常用 value baseline / GAE 估优势；PPO 本身不要求学习 reward model，也能用规则奖励。此处省略 value loss 与熵项。

数据：prompt + reward；对象：采样策略
GRPO

同 prompt 多回答，组内相对优势

A_i=\frac{r_i-\operatorname{mean}(r_{\mathrm{group}})}{\operatorname{std}(r_{\mathrm{group}})+\epsilon}

这是 outcome-reward 的组内标准化形式，ε 防止除零。组内全对或全错时，相对奖励优势为零；KL 等项仍可能有梯度。多回答 rollout 仍是计算成本的一部分。

数据：同一 prompt 的 group；对象：策略
DPO

离线偏好对，直接做相对概率目标

\mathcal L_{\mathrm{DPO}}=-\log\sigma\!\left(\beta[\Delta\log\pi_\theta-\Delta\log\pi_{\mathrm{ref}}]\right)

标准离线 DPO 优化不需新 rollout 或显式 reward model，但需固定 reference log-prob；可预计算。在线采样和 reference-free 变体要另看其目标定义。

数据：pair；对象：回答相对排序
RLVR

用可验证结果替代偏好评分

r = verifier(answer, tests / proof / checker)

数学答案、代码测试、约束满足等能自动判定；信号更硬，但 verifier 覆盖、奖励漏洞和任务可验证性会成为瓶颈。

数据：可执行任务；对象：可验证能力
把中间一步补上：奖励不可微，策略梯度为什么仍然存在？

先固定问题 x，假设 R(y) 是不直接依赖 θ 的外部奖励。生成结果 y 是离散序列，不能把采样得到的 token ID 当连续变量反传；但序列的概率 πθ(y|x) 对参数可微：

用只依赖 x、不依赖当前动作 y 的 baseline b(x) 替代奖励里的常数部分，可降低估计方差：E[b(x)∇logπθ(y|x)]=0。其他组内归一化的偏差需要另行分析；奖励若直接依赖 θ，还需计入相应导数。PPO 再通过 old-policy 概率比和裁剪处理多次使用采样数据的问题；KL、value loss 等项要按真实目标另加。

GRPO 与 RLVR 的分工：GRPO 用组内相对优势更新策略，RLVR 用可验证结果提供奖励。两者可以组合使用。

两个策略各有用途。old policy 是本批回答的采样策略，用在重要性概率比中；reference 是 KL 的锚点，通常固定。多次更新同批 rollout 后二者不能混用。实现中 KL 可写进奖励或单独作 loss 项，不能未经检查重复惩罚。

04

Reward Model 在学什么？

Bradley-Terry 把“A 比 B 好”转成可训练的二分类目标。

Bradley–Terry model
P(y_w\succ y_l\mid x)=\sigma\!\left(r_\phi(x,y_w)-r_\phi(x,y_l)\right)
\mathcal L_{\mathrm{RM}}=-\log\sigma(r_w-r_l)

成对目标只约束同 prompt 的分数差。对该 prompt 的所有回答加同一个常数，偏好概率不变；所以即使在训练分布内，跨 prompt 的绝对 reward 也不能天然比较，需另做校准或基线处理。

偏差

长度、格式、自信语气、引用样式可能比正确性更容易被评分模型学习。

分布外

policy 更新后会访问训练偏好未覆盖的新回答，reward model 可能给出外推错误。

Goodhart

策略可能利用评分规则的漏洞，获得高奖励但未完成预期任务。

06 / LEARNING SIGNAL

同一题全答对或全答错，还能学到什么？

组内相对优势用同题多个回答的差异作为学习信号。如果这一组奖励完全相同，中心化后的优势为零，这组 outcome reward 对应的策略项就没有区分信号。全对与全错的原因不同，下一轮题目难度与采样应分别分析；其他组、KL、熵项或过程奖励仍可能产生梯度。

动态采样的作用

DAPO 的配方保留有奖励差异的 prompt 组，继续采样以补足有效组。它提高了有效组比例，也改变了训练题目分布，并增加 rollout 成本。记录被过滤的题型与难度，防止训练只覆盖少数边界题。

探索为什么会减少

高概率路径被反复强化后，采样可能越来越相似。需要同时观察条件 token 熵、答案/策略多样性和任务成功率；更高熵也可能来自无意义随机输出。温度、熵正则、裁剪和采样分布分别作用于不同环节。

长度与截断

对序列先平均再平均样本，与全体 token 平均赋予长答案不同权重。若超长输出被截断后统一判错，还会把“没来得及完成”和“推理错误”混在一起。DAPO 专门讨论了 token 级目标和超长奖励处理。

稀疏奖励与长程信用

整条轨迹的结果奖励可关联到各个动作，但不直接指出哪一步造成成功。过程评分、价值基线、恢复轨迹和环境检查可提供更细信号；新增评分器也需要校准与防漏洞。

机制案例：DAPO（2025），具体消融、裁剪上下界与长度处理见页尾论文；这里没有复现其整套算法。

07 / POLICY VERSIONS

回答生成时，训练器已经更新了怎么办？

01 / ROLLOUT

记录行为策略

版本 v17 生成回答，保存所采动作的 log-prob、mask、结束原因和奖励。

02 / QUEUE

等待与评分

其他 worker 可继续生成。进入训练队列时模型可能已是 v20。

03 / UPDATE

核对分布偏移

用当前策略重算所采动作概率，检查概率比、版本差和有效样本数。

04 / REFRESH

更新生成权重

平衡 rollout 与训练速率，限定数据陈旧程度，过旧数据按协议处理。

同步流程要等待一批长短不同的回答完成；异步系统让生成和训练重叠，代价是样本来自不同版本的策略。AReaL（2025，2026 年修订）使用陈旧度控制与对应 PPO 变体。版本号相差几步只是调度指标，还需要检查概率分布变化；采样温度、top-p、停止规则及推理引擎的 log-prob 口径也要匹配。

QwenGyre：长任务的调度与轨迹怎样一起处理？

Qwen 的 2026-10-20 v2 论文把问题拆成两部分：在生成与训练之间弹性调配 GPU；用轨迹树保留分支的原始上下文，并避免共享前缀目标被重复计权。可训练目标按 token 的实际来源判断，harness 注入的 assistant 文本也不能自动算成策略采样。

任务结束或超时后，若保留的工作产物可以评估，就按任务规则评分，并绑定被检查的状态和分支。核验时同时检查任务成功率、目标去重、策略版本、角色切换成本与同预算耗时；GPU 更忙本身不能证明训练目标保持一致。

van Niekerk 等：RLSF v2。置信度提供训练信号，正确性和校准收益仍要独立评估。

过程反馈改变什么核验重点
推理时回看、批评与修订改变本次上下文和后续输出，通常不更新参数。固定总推理预算，比较最终完成质量与新增成本。
自生成偏好或筛选数据先形成训练数据，再按已声明的目标更新参数。冻结生成与评分版本，检查数据覆盖及同源偏差。
基于结果或反馈的 RL反馈进入奖励或优势，经策略目标更新参数。奖励定义、采样策略、归约与独立评估均应明确。

同一模型出题、作答和判分时，多个环节可能共享盲点。应保留训练反馈无法访问的测试、替代判分器及抽样人工核验，分别报告训练信号和真实任务结果。

怎样评估 RL 后训练的收益？

将训练 reward 与独立评估、能力回归和服务成本一起比较。

目标内

held-out verifier / 人类偏好 / rubric，且与训练 reward 来源独立。

能力

知识、代码、数学、长上下文、工具调用、格式遵循与语言能力回归。

行为

错误输出是否减少？拒答、长度、多样性、校准与安全是否在预期范围内？

计算

rollout 数、KL、response 长度、训练稳定性和服务成本是否可接受。

污染

verifier/judge 与训练数据是否共享答案、模式或同一评分者？

持续

多轮训练后是否出现 reward overoptimization、模式坍缩或格式单一。
